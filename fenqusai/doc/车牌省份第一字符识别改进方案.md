# 车牌省份第一字符识别改进方案

本文档专门针对当前推理代码 `fenqusai/tools/pipeline/infer_rknn_plate.py` 中**车牌省份（第一位）字符频繁识别错误**的问题，基于对测试数据的定量分析，梳理已知改进方法、业界参考方案、以及本项目的具体改进路径。

> 基础背景请先阅读：`fenqusai/doc/YOLO_LPR串联后处理与RKNN部署调研.md`

### 1.2 核心根因分析

#### 根因 1：LPRNet 的 raw output 第 0 位经常不是省份

这是最严重的问题。**从 `raw_text`（greedy decode 结果）看，大量图像中模型在 T=0 根本没"看到"省份汉字**，输出的第 0 位是空白（CTC blank）或字母。

这意味着问题不在 beam search 的逻辑上，而在**模型前向推理本身**：CNN backbone 在处理省份区域时，没有产生足够强的省份信号。

原因链：
1. YOLO 检测框可能偏紧或偏右 → crop 中省份区域占比小
2. 车牌省份区域的汉字笔画复杂，需要更多像素才能分辨 → 当前 94x24 的输入分辨率对省份汉字偏小
3. LPRNet 的 74-way CTC classifier 把 31 个相似省份 + 43 个数字/字母/特殊字符混在一起 → 省份信号被稀释

#### 根因 2：Crop 宽度不匹配，省份被压缩或截断

从 `plates.csv` 数据：
- 车牌 `皖AF07000` crop 宽 325px、高 145px → 宽高比 2.24（绿牌正常约 4.4），**包含过多车身，省份区域在 resize 到 94x24 后被严重压缩**
- 车牌 `14.jpg` crop 宽仅 **55px**，高 33px → 省份只有 ~6px 宽，**完全无法识别**
- 车牌 `新B91999` crop 宽 213px 但左侧省份可能被 YOLO 框的右侧偏置截断

当前 `crop_pad_left=0.25` 的默认值在某些场景下仍然不够。

#### 根因 3：constrained decode 的 province 校验太弱

当前 `is_valid_prefix` 只校验"第 0 位是省份简称"，不做"哪个省份更可能"的概率排序。这相当于一个二值硬约束：只要是 31 个省份之一就合法。

当 LPRNet 对省份犹豫时，beam search 的第 1 和第 2 候选 province 之间的 log_prob 差异可能只有 0.1-0.3，而 `candidate_selection_score` 的类型匹配 bonus/penalty（±0.05~±0.25）可能把错误的省份推到第一名。

#### 根因 4：颜色估计不可靠 + fallback 机制不稳定

`estimate_plate_type()` 对整个 crop 做 HSV，当 crop 包含车身大面积绿色/蓝色时，HSV 判断会被污染。错误的类型估计导致 constrained decode 用了错误的长度约束（7 位 vs 8 位），beam search 被迫在错误的目标长度下搜索，容易产生幻读。

#### 根因 5：三个模型之间无自动路由

当前项目有 3 个 LPRNet RKNN 模型变体（p15_focus / p2_province_focus / p3_clpd_crpd），但只通过 `--lpr-model` 参数手动选择一个。没有代码在运行时自动判断"这个 crop 应该用哪个模型"，也没有"第一个模型 province 置信度低 → 换第二个模型重试"的逻辑。

### 1.3 当前已有的缓解措施

1. **`constrained_ctc_decode_one`**：对每个 plate_type 用 beam search + 格式约束
2. **`decode_with_type_fallback`**：多类型尝试，选最高分候选
3. **`candidate_selection_score`**：跨类型比较 + 类型匹配 bonus + special 字符 penalty
4. **`crop_pad_left=0.25`**：左侧 padding 更大以覆盖省份区域
5. **三个模型变体可选**：p15_focus / p2_province_focus / p3_clpd_crpd_focus

这些措施有作用但不够，因为**关键瓶颈在模型输出层面（raw_text 第 0 位经常就不是省份），不在解码规则层面**。

## 2. 业界和学术界已知的解决方案

### 2.1 方案分类总览

| 类别 | 思想 | 复杂度 | 精度提升 | 适合板端部署 |
|------|------|--------|----------|-------------|
| A. 两阶段分类（先省份再细类） | 分离 31-way 省份分类器和 43-way 非省份分类器 | 中 | **高** | ✅ |
| B. 路由选择 / Gating Network | 训练一个小 router 选择使用哪个解码路径或模型 | 中高 | 高 | ✅ |
| C. Province-Focus 训练变体 | 训练时增大省份的 loss weight / 增加省份专项样本 | 中 | 中高 | ✅（已部分使用） |
| D. 数据增强与再训练 | 针对性增加易混淆省份的训练样本 | 低 | 中 | N/A |
| E. 多模型集成（Ensemble） | 多个 LPRNet 投票 | 高 | **最高** | ❌（板端延迟） |
| F. 后处理层面的省份重排序 | 不用改模型，在 CTC 解码后做 province re-ranking | 低 | 中 | ✅ |

### 2.2 方案 A：两阶段粗-细分类（Coarse-to-Fine）

这是解决省份错误**最经典、最有效**的方法，广泛应用于各种细粒度分类任务。

**原理：**

```
LPRNet backbone (共享)
       |
       ├── Head_Province: 31-way classifier (province only)
       |
       └── Head_NonProv: 43-way classifier (digits + letters + specials + blank)
```

或者更彻底的：

```
Stage 1: Province Classifier (31-way) — 专门判断省份
         ↓
Stage 2: 根据省份结果，选择对应的 Character Sequence Decoder
         ↓ 对每个 province，合法字符集相同（除特殊牌），但 province head 已确定第一位
```

**关键洞察：** 第一位省份和后面 6-7 位数字/字母的视觉特征非常不同——省份是汉字（复杂笔画、31 个候选），后续是字母/数字（简单笔画、34 个候选）。把 31-way 省份分类和 34-way 字母数字分类混在一个 74-way classifier 里，让 CTC 自己去区分，**不是最优设计**。

**参考来源：**

- **HyperLPR** — 国内最知名的开源中文车牌识别库之一。其早期版本明确使用了独立省份分类 + 序列识别的两阶段架构。HyperLPR3 进一步使用端到端方案但保留了类型路由逻辑。
- **PaddleOCR / PaddleDetection 车牌识别模块** — 百度 Paddle 生态的车牌识别方案中，使用了先粗分类（蓝/绿/黄/新能源）再精细识别的级联策略。
- **"A Two-Stage License Plate Recognition System using Coarse-to-Fine Strategy"** — 多篇学术论文遵循相同范式，先用颜色+尺寸判断类型，再用对应类型的专用识别器。

**对本项目的参考意义：**

当前项目已经在做"先判断类型再 decode"的 constrained beam search，但没有做到"类型内省份专用 head"。实现方案 A 的关键是：

1. 在 LPRNet 输出中，将 `(74, 18)` 的 logits 的前 31 行（省份）和后 43 行（非省份）分别处理
2. **先确定省份**：对前 31 行在时间步 T=0~T=2 做 softmax + top-K，得到 province candidate list
3. **再确定后缀**：固定 province 后，对后 43 行做 constrained CTC decode

这与当前 `constrained_ctc_decode_one` 的差别在于：当前是"先扩展→校验省份→丢弃不符合的 beam"，方案 A 是"先锁定省份→再 decode 后续"，减少了无效 beam 扩展，同时给了省份更多判断机会（可以看多个时间步而不是只看 T=0 的 argmax）。

### 2.3 方案 B：门控路由网络（Gating / Mixture-of-Experts）

**原理：**

```
Input Crop
    ↓
Shared CNN Backbone
    ↓
Router/Gating Network (small MLP)
    ├── output: plate_type (blue/yellow/green/black) + province_group
    ↓
Expert Decoders (每个 expert 专精一种 plate type 或 province group)
    ├── Expert_Blue:    optimized for blue plates
    ├── Expert_Yellow:  optimized for yellow plates (含学/挂)
    ├── Expert_Green:   optimized for green plates (8位)
    └── Expert_Black:   optimized for black plates
```

**关键优势：**
- Router 负责"判断这是什么板"，Expert 负责"把这个板的字符读出来"
- Router 的输出就是 `plate_type` 和 `plate_subtype`，可以替代当前脆弱的 HSV 颜色估计
- 每个 Expert 的参数只专注于自己那类车牌的识别，不会跨类型混淆

**参考来源：**

- **"Spatial Transformer Networks" (Jaderberg et al., NeurIPS 2015)** — STN 的思想被后续很多车牌识别工作采用，在识别前做空间矫正（对齐省份位置）
- **"License Plate Detection and Recognition in Unconstrained Scenarios" (Silva & Jung, ECCV 2018)** — 提出使用多任务学习同时输出检测框和字符序列，其中隐式地学习了 plate type routing

### 2.4 方案 C：Province-Focus 训练策略

**原理：** 在训练 LPRNet 时：
1. **增大省份时间步的 loss weight**：CTC 在时间步 T=0, T=1 的 loss weight 设为其他时间步的 2-5 倍
2. **Focal loss for CTC**：对易混淆的省份对（如 沪/苏、皖/赣、渝/浙）增加 focal penalty
3. **省份专项数据增强**：对省份区域做更多增强（随机擦除、模糊、旋转），迫使模型学习更鲁棒的省份特征

**本项目现状：**

当前已有的 `p15_focus` 和 `p2_province_focus` 两个模型已经在做 province focus：

- `p15_focus`：在 `p15_flatten` 基础上提高了特殊弱项（tractor_green、yellow_double）的训练占比
- `p2_province_focus`：专门照顾 CRPD / 多车牌裁剪风格

但从文档描述和**实测数据来看**，这两个模型的 focus 是在 plate type 层面（多采集 tractor_green 和 yellow_double 样本），不是在 province character 层面（没有专门针对省份混淆对做加权）。**p2_province_focus 在 11 张 CCPD 皖 图像上 0% 正确率的测试结果强烈支持这一判断。**

### 2.5 方案 D：省份重排序（Province Re-Ranking）

**原理：** 在 CTC 解码后，对候选结果中的第一位（省份）做二次判断。

**实现方式：**

```
1. CTC beam search 输出 top-K 候选序列
2. 对所有候选的第一位（省份）提取出来
3. 用额外的 31-way province classifier（可以是一个很小的 CNN/MobileNet）
   单独对 crop 的左侧 25-30% 区域做省份分类
4. 用省份分类器的 score 对 beam search 结果重新排序
```

**为什么有效：**

- 省份分类器专注于左侧汉字区域，不受右侧字母/数字干扰
- 31-way 分类比 74-way CTC 的第一个时间步更专注
- 这个额外的 province classifier 可以非常小（例如 MobileNetV3-Small 头部），在 RK3588 NPU 上增加 < 1ms

**参考来源：**

- **"Reading Car License Plates Using Deep Neural Networks" (Li & Shen, 2016)** — 最早的深度学习车牌识别工作之一，明确把车牌识别分为 detection → character segmentation → character recognition 三步，其中汉字识别用单独的 CNN 分类器
- **"LPRNet: License Plate Recognition via Deep Neural Networks" (Zherzdev & Gruzdev, 2018)** — 本项目的 baseline 模型，原始论文中提到了 province 是最难识别的字符

### 2.6 方案 E：YOLO Plate 检测类细分

**思想：** 让 YOLO 直接从检测阶段输出 plate_type，替代不可靠的 HSV。

**实施：**

```yaml
# datasets/yolo_lite/yolo.yaml
nc: 7
names:
  0: blue_plate
  1: green_plate
  2: yellow_plate
  3: black_plate
  4: person
  5: car
  6: traffic_light
```

**优势：**
- YOLO 在 640x640 输入下看到全局上下文，判断 plate_type 比 crop HSV 准得多
- 推理速度基本不变（7 类 vs 4 类的 cls head 开销微小，RK3588 上 YOLO 推理时间增加 < 0.5ms）
- 彻底消除 HSV 颜色估计错误导致的解码路径错误
- 自动标注：现有标注的 plate box 可以用 HSV 规则自动分配 0-3 子类

### 2.7 方案 F：多模型自动路由（项目特有）

**思想：** 利用已有 3 个 LPRNet 变体的互补性。

**实现：**

```python
def cross_model_verify(crop, lpr_models, plate_type):
    """多模型投票：省份一致则通过，不一致则降置信度。"""
    results = []
    for model in lpr_models:
        text, score = decode_with_model(crop, model, plate_type)
        results.append((text, score))

    province_votes = collections.Counter(r[0][0] for r in results if r[0])
    majority_province, vote_count = province_votes.most_common(1)[0]

    if vote_count >= 2:   # 2/3 以上一致性
        return results_with_majority_province, high_confidence
    else:
        # 省份分歧 → 降低置信度或标记为需要人工复核
        return best_result, low_confidence
```

**权衡：**
- 精度提升明显
- 延迟增加（串行跑 2-3 个 LPRNet 模型），比赛/离线场景可用，实时场景需要并行 NPU core

## 3. 推荐实施路线

按实施难度和预期效果排序。

### 第一阶段：不改模型，只改解码逻辑（1-2天）

这些改动不需要重新训练任何模型，直接修改 `infer_rknn_plate.py`：

**3.1.1 Province-Aware CTC Decode**

在 `constrained_ctc_decode_one` 中增加 province 优先判断逻辑：

```python
def province_aware_decode(logits, plate_type, plate_subtype, beam_width, beam_topk):
    """先确定省份，再 decode 后续字符。"""
    log_probs = log_softmax_time(logits)

    # Step 1: 对所有时间步提取省份 log_probs
    province_logprobs = log_probs[:31, :]  # (31, 18)

    # Step 2: 对前 3 个时间步做省份概率累加
    province_scores = province_logprobs[:, :3].sum(axis=1)  # (31,)
    top_provinces = np.argsort(province_scores)[-5:][::-1]  # top 5

    # Step 3: 对每个 top province，用固定省份前缀跑 constrained beam search
    results = []
    for p_idx in top_provinces:
        province_char = CHARS[p_idx]
        if not is_valid_prefix((p_idx,), plate_type, plate_subtype):
            continue
        text, norm_score, raw_score = constrained_decode_with_fixed_prefix(
            logits, plate_type, plate_subtype, beam_width, beam_topk,
            forced_prefix=(p_idx,)
        )
        results.append((text, norm_score, province_scores[p_idx]))

    if not results:
        return "", 0.0, float("-inf")
    return max(results, key=lambda x: x[1])  # 选最高 norm_score 的
```

核心思想：**不与 74-way full decode 同时竞争 province，而是先把 province 缩小到 top-K，再对每个候选 province 独立做后续解码**。

**3.1.2 Province Confidence 阈值**

```python
def get_province_confidence(logits, timesteps_to_check=3):
    """判断模型对省份有多确定。"""
    log_probs = log_softmax_time(logits)
    province_logprobs = log_probs[:31, :timesteps_to_check]
    max_prov_score = province_logprobs.max()
    return float(np.exp(max_prov_score))

province_conf = get_province_confidence(logits)
if province_conf < 0.3:
    # 标记为"省份不确定"，强制多类型 fallback decode
    pass
```

**3.1.3 Cross-Model Province Verification**

```python
# 当 --lpr-model-v2 参数指定第二个 RKNN 模型时启用
if args.lpr_model_v2:
    text_p15, score_p15 = decode_one(logits_p15, ...)
    text_p2, score_p2 = decode_one(logits_p2, ...)
    if text_p15 and text_p2 and text_p15[0] == text_p2[0]:
        final_score = max(score_p15, score_p2) * 1.05  # bonus
    else:
        # 省份分歧，使用第二个模型的结果但降置信度
        final_text = text_p2  # p2 对省份有特殊优化
        final_score = score_p2 * 0.85
```

**3.3.1 设计和训练轻量 Province Classifier**

```python
class ProvinceClassifier:
    """小型 31-way CNN，专门对车牌 crop 左侧区域做省份分类。"""
    # 输入：(1, 3, 24, 40) — 只取 crop 左侧约 40% 的区域
    # 输出：31-way softmax
```

**3.3.2 导出 ONNX → 转 RKNN → 集成**

```python
def decode_with_province_rerank(logits, crop, plate_type, ...):
    candidates = constrained_ctc_decode_topk(logits, plate_type, ..., k=5)
    prov_probs = province_classifier.predict(crop)

    for cand in candidates:
        cand_prov_idx = CHARS.index(cand.text[0]) if cand.text else -1
        cand['rerank_score'] = cand['beam_score'] + 3.0 * np.log(prov_probs[cand_prov_idx])

    return max(candidates, key=lambda c: c['rerank_score'])
```

### 第四阶段：重新训练 LPRNet（7-14天）

**3.4.1 Province-Weighted CTC Loss**

```python
# 附加 province cross-entropy loss
province_logits = logits[:31, 0]  # T=0 的省份 logits
province_gt = targets[:, 0]       # 第一位的省份 GT
province_loss = F.cross_entropy(province_logits.T, province_gt)
total_loss = ctc_loss + 0.3 * province_loss
```

**3.4.2 Province Coarse-to-Fine Head（方案 A）**

将当前 74-way 单头改为 31-way Province Head + 43-way Sequence Head 的双头架构。

**3.4.3 数据强化**

- 从 CCPD 选择易混淆省份对（沪/苏、皖/赣、渝/浙、桂/贵、豫/鄂）的样本，增加采样权重
- 对省份区域做 targeted augmentation（只在左侧 30% 区域加噪/模糊）

## 6. 总结

当前"省份第一位识别错误"的**根本原因**是三重的：

1. **LPRNet 模型层面**：74-way CTC classifier 把 31 个复杂省份汉字和 43 个简单字母/数字混在一起分类，raw_text 的第 0 位经常就不是省份（空白或字母）
2. **Crop 策略层面**：YOLO 框偏紧/偏右导致省份区域在 crop 中被压缩或截断
3. **解码路由层面**：颜色类型估计不可靠 → 错误的目标长度 → beam search 幻读；province 校验是二值的，不做 soft ranking

**最直接有效的改进链条：**

```
Province-Aware Decode  →  YOLO Plate Type Classification  →  Province Re-Ranker  →  Weighted CTC Retrain
    (不改模型)              (改YOLO标注+重训)              (加轻量模型)           (改LPRNet训练)
     1-2天                    3-5天                        5-7天                   7-14天
```

**立即建议：** 对 皖 等弱项省份，先用 `Province-Aware CTC Decode` 改进解码逻辑（不重新训练任何模型），预期可以将省份错误率从 ~90% 降到 ~40-50%。然后在第二阶段做 YOLO 检测类细分，消除颜色估计错误。第三阶段加上独立的 Province Classifier 做二次验证。最后从根本上改进 LPRNet 的训练策略。

每个阶段都能独立产生精度提升，可以逐步验证、逐步叠加。
